# PH2165: Sort members into regions

| Property | Value  |
|--|--|
| Package | [Philips.CodeAnalysis.MaintainabilityAnalyzers](https://www.nuget.org/packages/Philips.CodeAnalysis.MaintainabilityAnalyzers) |
| Diagnostic ID | PH2165 |
| Category  | [Readability](../Readability.md) |
| Analyzer | [SortMembersIntoRegionsAnalyzer](https://github.com/philips-software/roslyn-analyzers/blob/main/Philips.CodeAnalysis.MaintainabilityAnalyzers/Readability/SortMembersIntoRegionsAnalyzer.cs)
| CodeFix  | Yes |
| Severity | Error |
| Enabled By Default | No |

## Introduction

Every member of a top-level class, struct or record should live inside the region matching its kind and accessibility:

| Region | Members |
|--|--|
| `Non-Public Data Members` | Non-public fields, enums and delegates |
| `Non-Public Properties/Methods` | All other non-public members (methods, properties, constructors, events, indexers, nested types, ...) |
| `Public Interface` | All `public` members |

Inside a test class (a class with an attribute whose name ends in `TestClass`), the following regions are used as well:

| Region | Members |
|--|--|
| `Test Methods` | Methods with an attribute whose name ends in `TestMethod` (e.g. `[TestMethod]`, `[DataTestMethod]`) |
| `Test Mocks` | Non-public nested types with `Mock` in their name |
| `Test Classes` | All other nested types |

The classification is consistent with [PH2061](./PH2061.md). A member nested in a custom region inside its expected region (e.g. `#region Helpers` inside `#region Public Interface`) is accepted.

Only top-level types are analyzed; the members of nested types (e.g. test mocks) are left as they are. Types with `#if` or `#pragma` directives between their members are not analyzed, as reordering such members could change their meaning.

## How to solve

Apply the code fix. It removes the existing member-level regions of the type and regroups all members into the expected regions, by default in this order: `Test Mocks`, `Non-Public Data Members`, `Non-Public Properties/Methods`, `Public Interface`, allowed regions, `Test Methods`, `Test Classes` (see [Configuration](#configuration)). The relative order of members within a region, and their comments and documentation, are preserved. Spacing is preserved where possible: a region that already has the right members is kept verbatim, and a member that still follows the same member keeps its blank lines. Moved members are separated by one blank line, except between consecutive fields. Empty regions are not created.

## Example

Code that triggers a diagnostic:
``` cs
class BadExample
{
    public void DoWork() { }
    private int _count;
    private void Helper() { }
}
```

And the replacement code:
``` cs
class GoodExample
{
    #region Non-Public Data Members

    private int _count;

    #endregion

    #region Non-Public Properties/Methods

    private void Helper() { }

    #endregion

    #region Public Interface

    public void DoWork() { }

    #endregion
}
```

## Configuration

The name of each region can be changed in `.editorconfig`. Unset or empty values use the default name. Configured names should be distinct.

```
dotnet_code_quality.PH2165.test_mocks_region = Test Mocks
dotnet_code_quality.PH2165.non_public_data_members_region = Non-Public Data Members
dotnet_code_quality.PH2165.non_public_properties_methods_region = Private Interface
dotnet_code_quality.PH2165.public_interface_region = Public Interface
dotnet_code_quality.PH2165.test_methods_region = Test Methods
dotnet_code_quality.PH2165.test_classes_region = Test Classes
```

Additional regions can be allowed with a comma-separated list. Members inside an allowed region are never flagged, regardless of their kind or accessibility, and the code fix keeps each allowed region (including comments directly above it) unchanged, placing it (by default) after `Public Interface`:

```
dotnet_code_quality.PH2165.allowed_regions = Event Handlers, IDisposable Members
```

The order in which the code fix emits the regions can be changed with a string of digits, where each digit refers to a section of the default order:

| Digit | Section |
|--|--|
| 1 | `Test Mocks` |
| 2 | `Non-Public Data Members` |
| 3 | `Non-Public Properties/Methods` |
| 4 | `Public Interface` |
| 5 | Allowed regions |
| 6 | `Test Methods` |
| 7 | `Test Classes` |

The default is `1234567`. Omitted sections follow in their default order, so `12435` puts `Public Interface` before `Non-Public Properties/Methods`. Invalid values (unknown or repeated digits) fall back to the default.

```
dotnet_code_quality.PH2165.region_order = 12435
```

Note that [PH2061](./PH2061.md) only validates regions with the default names, so renamed regions are not checked by it.

The general ways of [suppressing](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings) diagnostics apply.
